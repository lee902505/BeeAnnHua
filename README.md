# 星辰日记 Web V0.10.3.6

## 农历系统本地化重写

V0.10.3.5 实机测试发现：
- 年份正常
- 月份正常

新增：
`js/lunar-calendar.js`

内建：
- 1900–2100 农历大小月资料
- 每年闰月
- 闰月 29 / 30 日
- 普通月 29 / 30 日
- 农历 → 阳历
- 阳历 → 农历
- 农历日期合法性判断

因此：
- 不受 CDN 是否可用影响
- 不受第三方版本 API 差异影响
- 手机 Safari 与电脑使用完全相同的农历数据

### 已验证
- 农历 1993 三月初一 → 阳历 1993/03/23
- 农历 1993 三月三十 → 阳历 1993/04/21
- 农历 2006 闰七月十一 → 阳历 2006/09/03
- 上述日期都可再从阳历正确转换回相同农历日期

本命盘与两人合盘 A / B 都使用同一套本地转换引擎。

# 星辰日记 Web V0.10.3.5

## 农历月份 / 日期选项修正

V0.10.3.4 实机测试发现：
- 农历年份可选择
- 选择年份后「月份」与「日期」没有产生选项

### 原因
上一版农历 UI 使用了不同版本 `solarlunar` 曾提供的内部辅助方法，例如：
- `leapMonth`
- `leapDays`
- `monthDays`
- `toChinaMonth`
- `toChinaDay`

当前 3.1.0 浏览器版稳定公开的核心转换 API 是：
- `solar2lunar`
- `lunar2solar`

年份改变时调用不存在的辅助方法，导致月份生成程序中断。

### V0.10.3.5 修法
现在完全不依赖上述辅助方法。

系统使用：
`农历日期 → 阳历 → 再转回农历`

只有当：
- 年
- 月
- 日
- 是否闰月

全部能完整 round-trip 回到原值，才视为合法农历日期。

因此系统可以自行判断：

- 该年闰哪一个月
- 没有闰月时不显示任何错误闰月
- 平月 29 天或 30 天
- 闰月 29 天或 30 天
- 不存在的农历日期不会进入星盘计算

### 操作
农历模式：
1. 选择年份
2. 月份自动出现
3. 若该年有闰月，会自动插入「闰X月」
4. 选择月份
5. 日期自动出现 29 或 30 天
6. 选择日期
7. 下方立即显示「换算阳历」

### 浏览器载入
`solarlunar 3.1.0` 改用官方文档示例的 UMD 浏览器路径（unpkg），并保留 jsDelivr fallback。

### 设计选择
不开放自由文字输入农历日期，以避免：
- 不存在的闰月
- 大小月错误
- 31 日等无效农历日期

保留点击选择式年 / 月 / 日，手机使用最直接。

V0.10.3.4 的中国省 / 市 / 区县出生地搜索、Bark、公历/农历转换、12宫深度解读与其他功能全部保留。

# 星辰日记 Web V0.10.3.2

## iPhone 原生日期/时间 + 城市结果修正版

根据 iPhone 实机截图确认，前一版问题并不是普通 grid 宽度，而是：

1. iOS Safari 原生 `input[type=date] / input[type=time]` 仍保留内部 intrinsic width，导致右侧圆角被推出 viewport。
2. 城市搜索结果采用 absolute 浮层，手机键盘开启时容易与下方控件重叠；经纬度 / 时区第二行也可能被视觉上吃掉。

本版修正：

- 日期与时间加入 `.astro-native-input-shell` 外层。
- 可见圆角、边框、背景由普通 HTML 容器绘制，原生 input 被安全裁切在容器内。
- 保留 `type=date / type=time`，点击仍使用 iOS 原生日期与时间选择器。
- 手机版星盘输入 grid 改为 block flow，彻底避开 WebKit grid intrinsic width。
- 城市建议列表在手机改为 normal flow，不再浮在后续项目上。
- 城市建议每笔强制保留：
  - 城市 / 国家
  - 经纬度
  - IANA 时区
- 选定城市后，经纬度与时区显示为独立资讯条。
- 同样修复两人合盘 A / B 的日期与时间输入。
- 手机触控城市选择改用 Pointer Event / touch fallback。
- CSS 与全部本地 JS 使用 `?v=0.10.3.2` 强制刷新，避免 Safari / GitHub Pages 使用旧缓存。

V0.10.3 的 12 宫深度解读、宫主星、行星落宫、Bark、玩家资料等全部保留。

# 星辰日记 Web V0.10.1

## 新增：Stellar Compatibility Index 合拍指数

V0.10.1 在 V0.10 两人合盘上新增 0–100 的合拍指数。

### 五个分项
- 情绪默契
- 沟通理解
- 亲密吸引
- 长期稳定
- 成长互补

### 不同关系类型使用不同权重
恋爱／暧昧、情侣、夫妻／长期伴侣、朋友、工作伙伴不会使用同一套百分比。

例如情侣模式：
- 情绪 25%
- 沟通 20%
- 吸引 25%
- 稳定 20%
- 成长 10%

工作伙伴模式则提高沟通与稳定的比例。

### 计分不是简单「好相位 +1 / 坏相位 -1」
每个跨盘相位会依：
1. 行星组合重要度
2. 相位性质
3. 实际 orb 紧密度
4. 所属分项
5. 关系类型权重

共同计算。

### Orb
越接近 0° 的精确相位，贡献越强；
越靠近当前相位容许度边缘，影响会平滑下降。

### 合相
合相不会自动加分。
例如：
- 太阳／月亮、月亮／金星、金星／火星等，通常可增加协调或吸引。
- 月亮／冥王星、月亮／火星、土星与个人星体等，会依「情绪、吸引、稳定、成长」不同分项分别处理。

### 0–100 的意义
合拍指数表示「占星互动的自然顺畅程度与需要磨合的压力」，
不是：
- 恋爱成功率
- 婚姻概率
- 会不会分手的预测
- 现实关系结果保证

### UI
- 合盘结果顶部新增大号 0–100 指数
- 显示五个分项
- 显示当前关系类型的五项权重
- 新增可展开「计分依据」
- 继续保留完整跨盘相位解析

# 星辰日记 Web V0.8

## 本版目标：星座测算核心

V0.8 正式加入出生资料计算，先完成西洋占星最常使用的三个核心位置：

- ☉ 太阳
- ☽ 月亮
- ASC 上升

本版仍不新增任何图片素材。

## 计算方式

### 天文计算
- 热带黄道（Tropical Zodiac）
- Astronomy Engine JavaScript 2.1.19
- 太阳：出生瞬间的视地心真黄经
- 月亮：出生瞬间的地心真黄道经度
- 上升：Greenwich Apparent Sidereal Time + 出生地经度 → 当地恒星时，再配合纬度与黄赤交角计算东方地平线与黄道交点
- 出生地时区使用 IANA timezone，并通过浏览器 Intl 处理历史夏令时

### 出生时间未知
- 太阳、月亮以出生地当地 12:00 作为近似计算点
- 额外检查当地 00:00 与 23:59 的月亮星座
- 如果月亮当天跨星座，会明确显示两个可能星座
- 上升不猜测、不使用「每两小时一个星座」查表，直接显示无法计算

## V0.8 页面输入
- 出生日期
- 出生时间
- 出生城市
- 不知道出生时间
- 手动纬度 / 经度 / IANA 时区（城市列表找不到时使用）
