# 星辰日记 V0.17.2 最终检查报告

## 版本目标

V0.17.2 将固定每日任务升级为「每日任务 2.0」，并新增今日熟练度与火车重置券：

- UTC+8 每日固定抽取 5 项任务。
- 任务依玩家等级、好友上下文与类别配额选择。
- 每日可免费更换 1 项尚未完成的任务。
- 每完成 1 项任务获得 20 点今日熟练度。
- 40 熟练度：金币 ×20；80 熟练度：EXP +30；100 熟练度：火车重置券 ×1。
- 火车重置券用于刷新未发车列车的倍率与货物需求，已装货物先完整退回背包。
- V0.17.1 的每日农友互助 EXP 50 上限继续独立存在。

## 深度检查结果

### 1. JavaScript

- `js/` 共 33 个 JavaScript 文件全部通过 `node --check`。
- `farm.js` 的每日任务、熟练度领取、免费换任务、火车重置券、pending-op / revision conflict replay 路径均完成静态复核。
- 修正 `ensureDailyTaskPlan()` 在清洗 taskIds 后未回报状态变化的边界问题，确保规范化后的任务计划可正确持久化。
- 火车刷新算法加强：优先保证「倍率」与「货物组合／需求量」两部分都发生变化；保留安全 fallback，避免极端低等级作物池无法生成订单。
- 火车刷新历史维持最后 30 笔，避免运行期间 history 无限制增长。

### 2. 每日任务池

- 当前任务池：30 项，Task ID 30/30 唯一。
- 类别：农田 15、农友 8、经营 3、火车 4。
- 自动模拟 Lv.1 / 2 / 3 / 4 / 5 / 8 / 10 / 12 / 25 / 100，分别有／无好友，共 28 个日期：560 组任务计划。
- 560/560 均能生成 5 项不重复任务，没有空计划或重复 Task ID。
- Lv.1 无好友也始终有足够可完成任务；社交任务不会在没有好友上下文时强制出现。
- 指定作物任务门槛与目前作物解锁等级一致。

### 3. 今日熟练度

- 完成任务自动形成 20 / 40 / 60 / 80 / 100 熟练度进度。
- 40、80、100 三个里程碑可独立领取，领取状态写入 `daily.masteryClaimed`，防止重复领取。
- 100 熟练度奖励写入既有 `supplies`：`trainResetTicket ×1`。
- 任务奖励与熟练度奖励相互独立；无需先领取单项任务奖励才计算熟练度。
- V0.17.1 的「每日农友互助 EXP 0/50」不与熟练度混算。

### 4. 每日免费换任务

- 每日最多一次，状态为 `daily.rerollUsed` / `daily.rerollSlot`。
- 已完成任务不可更换。
- 新任务不会与当天其余 4 项 Task ID 重复，并优先从同类别／不同 family 中挑选。
- 换任务动作纳入 pending-op，revision conflict 时可重放；另一装置已使用换任务时不会重复取得次数。

### 5. 火车重置券

- 仅可用于 `ready` 且尚未发车的列车。
- 使用前检查券数量；每次消耗 1 张。
- 已装载货物会按每节车厢 `loaded` 数完整退回玩家背包。
- 刷新后重新生成倍率、车厢作物与需求数量。
- 对 9 个等级区间 × 28 天 × 2 月台 × 8 个 generation，共 4,032 个订单情境做确定性模拟；4,032/4,032 都能在 36 次候选上限内找到「倍率与货物需求均不同」的新订单，实测最慢 5 次候选。
- 刷新动作纳入 pending-op / appliedOps，避免 F5 或 revision conflict 导致重复扣券／重复退货。
- 背包与车站均显示当前火车重置券数量。

### 6. 每日指标接线

已检查任务指标都有对应的实际游戏行为累积：

- 播种／指定作物播种
- 收成／指定作物收成
- 出售
- 偷菜
- 好友助力浇水
- 好友照料（浇水＋除虫）
- 使用肥料
- 种植蔬果盲盒
- 装满火车车厢
- 完成火车发车
- 每日首次拜访不同农友

真人好友的助力浇水／除虫日计数继续由 Supabase authoritative helper 返回；NPC 行为继续沿用本地优先＋pending-op 合并。

### 9. 安全边界

- 本版没有加入 service-role key、Supabase secret、Bark device secret 或数据库密码到浏览器端。
- 既有架构仍属于「玩家完整 farm state 存在 `farm_saves.state`，大部分单机经济动作由客户端提交」；因此对熟悉开发者工具的恶意玩家，完整经济防作弊仍不是 server-authoritative。这是项目既有架构限制，并非 V0.17.2 新回归。
- 好友多人互动仍由现有 Supabase RPC 做服务器验证。

## 结论

静态与确定性逻辑检查未发现阻止 V0.17.2 部署的致命问题。建议部署顺序：

1. 既有 025 已成功执行的前提下，仅执行 026。
2. 部署 V0.17.2 静态文件。
3. 实机重点测试：每日 5 项任务、免费换任务、40/80/100 熟练度领取、火车装货后使用重置券、手机端任务／车站按钮布局、跨装置同日任务一致性。
