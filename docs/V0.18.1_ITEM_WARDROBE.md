# V0.18.1 — 农场物品与衣橱拥有权

## 目标

把「玩家拥有某件时装」与「目前穿着哪件时装」拆开，并让火车重置券、时装都进入稳定 Item ID 体系，以便未来系统邮件、公告补偿、活动与盲盒共用同一套奖励编号。

## 存档结构

```json
{
  "supplies": {
    "trainResetTicket": 1
  },
  "wardrobe": {
    "outfits": {
      "default": true,
      "halloween": true
    }
  },
  "avatar": {
    "gender": "female",
    "outfit": "halloween"
  }
}
```

- `wardrobe.outfits`：永久拥有权。
- `avatar.outfit`：目前穿着。
- `default` 永远为 `true`。
- 邮件领取时装时只改变拥有权，不自动改变 `avatar.outfit`。

## Item ID

- `#4004` `supply.train_reset_ticket` — 火车重置券。
- `#5001` `outfit.default` — 星辰农夫基础造型，所有玩家永久拥有。
- `#5002` `outfit.mid_autumn` — 中秋节造型，编号预留。
- `#5003` `outfit.halloween` — 万圣节造型，编号预留。
- `#5004` `outfit.christmas` — 圣诞造型，编号预留。

5002–5004 当前 `mail_enabled=false`。等男女 Sprite Sheet 完成并接入 `AVATAR_OUTFITS` 后，再用后续 migration 开启发放，避免玩家提前取得无法显示的服装。

## 衣橱行为

衣橱卡片有四种状态：

1. **使用中**：当前造型，按钮停用。
2. **已拥有**：显示「套用」按钮。
3. **未拥有**：不能套用。
4. **尚未开放**：Item ID 已保留，但素材/活动尚未发布。

玩家点击「套用」才会写入 `avatar.outfit`，不再点击整张卡片立即换装。

## 后端奖励

`mail_item_catalog.reward_kind` 新增 `outfit`。当邮件附件未来包含时装 Item ID 时，领取 RPC 会写入：

`state.wardrobe.outfits.<state_key> = true`

永久时装 `max_quantity=1`。重复拥有的邮件奖励仍是幂等的 `true`，不会产生第二件；盲盒重复补偿规则留给后续活动奖池版本决定。
