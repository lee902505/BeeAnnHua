# V0.19.0 — Seasonal Decoration System

## Scope

This release extends the existing fixed 8-slot farm-decoration system instead of creating a second placement engine.

### New Item IDs

- 6001 `decoration.mid_lantern`
- 6002 `decoration.mid_rabbit`
- 6003 `decoration.mid_osmanthus`
- 6004 `decoration.mid_moon_lamp`
- 6005 `decoration.halloween_pumpkin`
- 6006 `decoration.halloween_ghost`
- 6007 `decoration.halloween_candle`
- 6008 reserved
- 6009 `decoration.christmas_tree`
- 6010 `decoration.christmas_gifts`
- 6011 `decoration.christmas_snowman`
- 6012 `decoration.christmas_lamp`

## Release gates

Mid-Autumn 6001–6004 are visible in the normal decoration shop.
Halloween and Christmas entries are deliberately `shopVisible:false`, but remain valid farm items and can be granted by GM/system mail for private testing.

No hidden seasonal item is purchasable through a crafted `data-buy-decor` action because `buyDecoration()` also rejects `shopVisible:false` at the data layer.

## Persistence

Decoration inventory remains inside the existing farm save:

```json
{
  "decorations": {
    "owned": { "mid_lantern": 1 },
    "slots": ["mid_lantern", null, null, null, null, null, null, null]
  }
}
```

GM mail claims increment `decorations.owned.<state_key>` and never auto-place an item.

## Database

Run `supabase/migrations/20260928_030_seasonal_decorations.sql` after migration 029.
It extends the mail catalog with the `decoration` category/reward kind, registers Item IDs 6001–6012 (excluding reserved 6008), updates the claim engine, and allows the new decoration IDs through the sanitized friend-farm layout.
